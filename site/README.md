# tidy-one site

The landing page for tidy-one: one static English page with a light and a dark theme, no framework and no build server. A small Python script turns one HTML template, one copy file and the client list into plain HTML.

```
site/
├── build.py            # renders the template, inlines icons/mascot/logos, draws favicon + OG image, writes dist/
├── i18n/
│   ├── en.json         # all copy, used verbatim
│   └── clients.json    # "Works with" list: [{name, url, logo}] in display order
├── src/
│   ├── template.html   # the page ({{ key.path }} placeholders)
│   └── assets/
│       ├── site.css    # Sage Minimal styles, light + dark tokens
│       ├── site.js     # theme toggle, menu, hero pixel field + mascot, footer game
│       ├── mascot/     # mascot poses: mascot-<pose>.svg (40 x 36, theme variables) + 16x PNGs
│       ├── logos/      # client logos (Simple Icons, fill="currentColor") + ATTRIBUTION.md
│       ├── favicon.svg            # generated by build.py (the mascot's head)
│       ├── og.png                 # generated by build.py (1200 x 630)
│       └── apple-touch-icon.png   # generated by build.py
├── tools/
│   ├── mascot.py           # draws the mascot poses (needs Pillow, see below)
│   └── game-selfcheck.js   # browser self-check for the footer game
└── dist/               # build output (safe to delete; build.py recreates it)
    ├── index.html      # the page (/)
    ├── en/index.html   # redirect to ../ (the page used to have /en/ and /zh/ versions)
    ├── zh/index.html   # redirect to ../
    ├── assets/
    ├── robots.txt, sitemap.xml, .nojekyll
```

## Build

Python 3.9+ standard library only.

```sh
python3 site/build.py
```

The script stops with a message if a placeholder in the template has no copy, an icon bitmap is not 16 x 16, a mascot SVG is not in the generated format, or a logo file is not a single 24 x 24 `currentColor` SVG.

Canonical, `og:url`, `og:image`, the sitemap and `robots.txt` use absolute URLs built from `SITE_BASE_URL`. It defaults to the GitHub Pages project URL, `https://junwonkim07.github.io/tidy-one` (served under the `/tidy-one/` base path). To build for another host, set it (the older name `SITE_URL` still works):

```sh
SITE_BASE_URL=https://tidy-one.example python3 site/build.py
```

Every link inside the page is relative (`assets/…`, `./`, `#section`), so the same `dist/` works at `/` on a local server and under `/tidy-one/` on GitHub Pages. `build.py` also writes `dist/.nojekyll` so Pages serves the files as they are. The old `/en/` and `/zh/` URLs keep working: they are small pages that send the visitor (and any `#section`) to `../`, with a `noindex` and a canonical link to the page.

On a project site, crawlers only read `robots.txt` at the host root (`junwonkim07.github.io/robots.txt`), so the copy in `dist/` matters only with a custom domain. Submit `sitemap.xml` in Search Console instead.

## Preview

```sh
python3 -m http.server 4310 --directory site/dist
# open http://localhost:4310/
```

To check the GitHub Pages base path, serve a copy from a `tidy-one/` subfolder:

```sh
mkdir -p /tmp/pages/tidy-one && cp -R site/dist/. /tmp/pages/tidy-one/
python3 -m http.server 4311 --directory /tmp/pages
# open http://localhost:4311/tidy-one/ and /tidy-one/en/ (redirects)
```

## Deploy

`.github/workflows/pages.yml` runs `python3 site/build.py` with `SITE_BASE_URL=https://junwonkim07.github.io/tidy-one` and publishes `site/dist` to GitHub Pages on every push to `main` that touches `site/`.

## Edit copy

Change the text in `i18n/en.json` and rebuild. Lists (`features.*.chips`, `status.done`, `status.next`) can grow or shrink; each entry is `[icon, text]`, where `icon` names one or more icons from `ICONS` in `build.py` (space-separated). In headings, `|` marks a phrase that moves to the next line as a whole and `||` a sentence that starts a new line when it doesn't fit beside the previous one (`build.py` turns them into `<span class="ph">` and `<span class="sen">`).

"Works with" comes from `i18n/clients.json`. `logo` is a path under `src/assets/` (for example `logos/claude.svg`) or `""`, in which case the name is set as a wordmark in the logo's place. Record the source and license of every new logo in `src/assets/logos/ATTRIBUTION.md`.

## Mascot

The mascot is a small server box with a screen face and a note card on top, at 40 x 36 pixels, derived from the character in the GitHub banner. `tools/mascot.py` draws every pose (`idle`, `blink`, `wave`, `search`, `sleep`, `tidy` and `tidy2`, the second broom frame) as an SVG whose fills are CSS variables with light fallbacks (`--m-line`, `--m-body`, `--m-shade`, `--m-screen`, `--m-eye`, `--m-glint`, `--m-smile`, `--m-cheek`, `--m-card`, `--m-card2`), plus 640 x 576 PNGs:

```sh
uv run --with pillow python site/tools/mascot.py site/src/assets/mascot /tmp/mascot-sheets
```

`build.py` reads those SVGs and puts every pose once into a hidden sprite at the top of the page; each use is `<svg viewBox="0 0 40 32"><use href="#m-idle"/></svg>`, so it follows the theme. The viewBox drops the four empty rows under the feet, so the feet stand on whatever line the mascot sits on (the broom's bristles poke one pixel below). Display sizes are whole multiples of the grid (`--mpx`: 2, 3, 4 or 5 screen pixels per art pixel). A 16 x 16 head (`HEAD` in `build.py`) is the brand mark, the favicon and, at 4x, the touch icon.

## How it behaves

- **Theme.** Light by default; dark when the system asks for it. The sun/moon button in the header (`aria-pressed`, named "Dark theme") overrides the system and remembers the choice in `localStorage` (`tidy-one:theme`, wrapped in try/catch). A tiny inline script in `<head>` applies a stored choice before the first paint, so there is no flash of the wrong theme. Every colour is a custom property on `:root`; the dark values apply under `@media (prefers-color-scheme: dark) :root:not([data-theme="light"])` and `:root[data-theme="dark"]`. The privacy band and the footer band are dark surfaces in both themes. Text meets WCAG AA in both themes.
- **Hero pixel field.** A `<canvas>` draws pixels that hang from the hairline in loose clouds. Scrolling tidies them into 3 x 3 tiles sorted from the darkest tone to mist. A soft bloom sits under the pixels: they are drawn again, larger, into a canvas a fifth of the size, blurred there (when the browser supports canvas filters) and scaled up with smoothing, so it costs little. On paper the bloom is a faint sage haze; on dark the lighter pixels glow in their own tone. The colours are read from CSS variables (`--px-0` to `--px-4`, `--px-empty`, `--px-glow`, `--px-glow-alpha`, `--px-glow-blend`) and the field is repainted when the theme changes. After load or a scroll the scattered pixels drift slowly (about 10 fps) for under 5 seconds, then the loop sleeps until the next scroll; it also stops when the canvas is off screen. With `prefers-reduced-motion` it draws the tidy end state once and ignores scrolling.
- **Mascot.** In the hero it stands on the field's hairline. It blinks now and then (a few blinks, then it rests until the reader moves the pointer, scrolls or the hero comes back into view), waves while the pointer is on it or on a call to action, or while a call to action has focus, and sweeps while the field tidies: the two broom frames swap with scroll progress and it slides a few art pixels along the line. Elsewhere it searches beside "How it works", sleeps in the privacy band, holds its broom next to the roadmap, hosts the footer game (it waves when the board is tidy) and stands beside the large wordmark in the footer band. With reduced motion it neither blinks nor sweeps.
- **Footer game.** Twelve pixel buttons are scattered in a field. A click or tap, or Enter/Space on a focused pixel, sends it to its own slot in a 4 x 3 grid. Placing the last pixel hides the empty field, centres the board, announces the done message through a live region and focuses "Scatter again". That button, or the scatter icon beside the counter at any time, puts every piece back into the field at fresh random, non-overlapping spots and resets the count. (Earlier the field was measured while it was still hidden behind the done message, so every piece got a NaN position and they all piled up in a corner.) To check it, evaluate `tools/game-selfcheck.js` on the built page: it runs 10 solve-and-scatter cycles, three mid-game scatters and one scatter during the pause before "All tidy.", and reports `{ ok, cycles, errors }`.
- **Motion.** Nothing loops forever: the scroll-hint arrow nudges twice, the mascot's blinks stop after a few, and in "How it works" a packet runs once down each wire, in order, whenever the steps come into view. All of it is off with `prefers-reduced-motion`.

## Design notes

- Palette "Sage Minimal": `#CAD2C5` mist, `#84A98C` sage, `#52796F` deep sage, `#354F52` pine, `#2F3E46` slate. Light: background `#F8F9F7`, text slate and pine, small labels deep sage (4.6:1). Dark: background `#1E2A2F`, surfaces `#243238` and `#2F3E46`, text `#E6ECE8` and mist, labels sage (5.6:1).
- Type: Inter Tight only, including the small uppercase labels (12px, weight 600, letter-spacing .14em). No monospace anywhere. The font stylesheet loads without blocking first paint (`rel=preload` switched to a stylesheet on load, with a `<noscript>` fallback) and uses `font-display: swap`.
- Icons: a set of 16 x 16 pixel icons (`ICONS` in `build.py`): one-pixel outlines in `currentColor` with an accent fill (`--icon-accent`), drawn at 16, 32 or 48 px. They mark the section labels, navigation, features and file types, steps, privacy points, roadmap items, footer links and the theme switch. Icon-only controls have an accessible name and a tooltip.
- Client logos are Simple Icons marks inlined with `fill="currentColor"`, so they take the text colour in both themes; see `src/assets/logos/ATTRIBUTION.md`. tidy-one is not affiliated with these products, and the page says so.
- Footer: brand, tagline and author on the left, project links on the right, then a full-bleed band whose wavy top edge carries a soft mist-sage-deep aura (an inline SVG with blurred copies of one wave path) and holds the large gradient wordmark next to the mascot.
- Buttons, badges and chips have pixel-stepped corners (`clip-path` on a pseudo-element, so focus outlines are not clipped).
- No JavaScript libraries.
